# Deployment review template

These files are **examples only**. They have not been installed, started, or tested against the public host. Replace `relay.example.org` with a dedicated owner-chosen hostname and obtain a certificate for that exact name. The existing `za.bytebuilders.co.za:443` serves phpMyAdmin and presents the wrong certificate to external clients; it must not be taken over by this relay. A different port on `za.bytebuilders.co.za` is also unsafe because browser cookies are shared across ports. Use a dedicated hostname, or keep the relay private.

The systemd service binds the Python relay to `127.0.0.1:27443` with TLS. It uses a dynamic unprivileged account, a private state directory, and read-only copies of the Let's Encrypt certificate and key through systemd credentials. It needs a supervised Python environment at `/opt/notabackdoor-relay/venv` containing the pinned `aiohttp` dependency. Certificate renewal must restart the service so its credential copies refresh. Protect the SQLite registry and route-signing key in `/var/lib/notabackdoor-relay` as credentials, and test restoration before use.

The Nginx vhost terminates the public HTTPS connection and establishes a **second verified TLS connection** to the loopback relay. It overwrites `X-Forwarded-For` with one client IP, passes the exact external Host, disables access/error path logging and request/response buffering, and allows three-hour streaming downloads. An HTTP port-80 redirect is deliberately omitted because an `http://` pairing URL would otherwise expose its secret path before redirect; choose a certificate-renewal method without such a route. The template has no automatic install steps and must be checked against the host's existing Nginx configuration with `nginx -t` before any rollout.

The relay itself still validates external Host/Origin/CSRF, caps requests, and authenticates devices. The public operator can nevertheless see all panel traffic in memory. Firewall policy should keep 27443 reachable only from local Nginx, and the service process must have no workspace, Modrinth, SSH management, or Minecraft server credentials. The default Python CLI bind is also loopback. SQLite-backed token buckets persist login/enrollment limits across restarts; a five-per-minute global pair-start rate stays below the 100-pending-pair cap. **Do not deploy this template yet:** a dedicated hostname/certificate and browser/upstream TLS verification are missing. A distributed attacker can still consume the enrollment budget. Test certificate rotation and real server/client behavior before public rollout; the current relay tests use localhost TLS.
